## 五、开发工作流与协作机制

### 1. Git工作流规范

#### （1）分支管理
- **主分支**：`Campus-Second-hand-Recycling-Low-Carbon-Credit-System`（生产分支）
- **开发分支**：基于任务创建功能分支
- **命名规范**：`feature/功能名` 或 `bugfix/问题名`

#### （2）提交规范
```
提交消息格式：[类型] 功能描述

类型包括：
- feat: 新功能
- fix: 修复bug
- refactor: 代码重构
- style: 格式调整
- docs: 文档更新
- test: 测试用例

示例：
feat: 实现商品搜索功能
fix: 修复点赞后无法取消的问题
docs: 更新API文档
```

#### （3）代码审查流程
1. 开发者提交代码到自己的分支
2. 创建 Pull Request（PR）
3. 组长 (蔺钊宇) 进行代码审查
