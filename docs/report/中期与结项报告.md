## 一、项目概述

### 1. 项目背景

#### 1.1 项目来源：

&emsp;&emsp;本项目的选题来源于高校校园中普遍存在的资源浪费与交易效率低下的实际问题。毕业季期间，由于搬运成本高、处理时间短，大量具有较高使用价值的课本教辅、小型电器（如台灯、电风扇）、生活用品被当作废品处理甚至直接丢弃，造成了极大的资源浪费。每年入学的学弟学妹或在校生，往往需要支付全价购买新的教材和生活设施。虽然校内存在零散的“跳蚤市场”或微信群，但由于信息碎片化、缺乏统一的管理平台，导致供需双方难以精准匹配，交易效率低下。
&emsp;&emsp;通用的二手平台（如闲鱼、转转）因缺乏校园身份背书，学生在交易时往往存在安全顾虑，因此，本小组决定设计并实现一套面向校园场景的二手交易系统。

#### 1.2 应用场景：

&emsp;&emsp;本系统主要应用于高校校园内部，面向在校本科生及研究生。具体使用场景包括：

（1）**毕业季闲置处理：** 毕业生在离校前集中发布教材、生活用品等物品信息，快速找到买家，减少直接丢弃造成的浪费。
（2）**日常二手交易：** 在校生可以在任何时间发布或购买二手物品，如教材、考试资料、体育用品、电子产品等，形成常态化的校园循环交易网络。

#### 1.3 现实意义：

（1）**资源节约：** 本系统通过数字化的物品发布与撮合机制，将闲置资源精准导流至有需求的学生手中，减少了因信息不畅导致的物品浪费，提高了校内资源的整体周转效率。
（2）**校园管理：** 系统可以减轻毕业季校园垃圾处理的压力，同时通过规范的线上交易流程和物品审核机制，提升校内二手交易的安全性和秩序。


### 2. 系统目标

#### 2.1 主要目标

**（1）构建统一的校园二手交易渠道**

- 为在校生提供一个集中的物品发布、浏览、搜索与购买平台，改变当前依赖微信群、线下摆摊等零散交易方式的现状。
- 支持物品按分类（教材、生活用品、电子产品等）筛选及关键词检索，提高供需匹配效率。
- 每个物品详情页提供图文展示及留言功能，方便买卖双方沟通，降低信息不对称。

**（2）实现交易流程的自动化与规范化**

- 用户可进行模拟充值，购买时系统自动校验余额并完成扣款，交易记录自动写入数据库。
- 管理员可对违规物品进行下架处理，对异常用户进行禁用，维护平台基本秩序。
- 订单生成后，买卖双方可追溯交易详情，减少售后纠纷。

**（3）提升校园资源利用率并增强环保意识**

- 通过平台撮合，将毕业季等场景下闲置的教材、电器、生活用品引流至有需求的学生手中，减少直接丢弃造成的资源浪费。
- 激励学生更积极地参与二手循环交易，在校内营造低碳环保的氛围。
- 为学校提供一定程度上的垃圾减量支持，降低毕业季清理压力。

**（4）为小组提供完整的软件开发实践案例**

- 采用 Spring Boot + MySQL + HTML/CSS/JS 技术栈，按 MVC 三层架构组织代码，锻炼后端业务逻辑开发、数据库设计及前端交互能力。
- 使用 Git 进行版本管理，GitHub 托管代码，规范 commit 记录，模拟真实团队开发流程。
- 最终产出包括可运行的系统、项目文档（计划书、需求分析、设计说明、测试报告、软件说明书）及过程性材料。

#### 1.2 业务流程

**物品发布与购买**


### 2. 非功能需求

#### 2.1 性能要求

- 在校园局域网环境下，页面跳转及主要操作（登录、发布、搜索、下单）的响应时间应小于2秒。
- 系统应支持至少50人同时在线使用，无明显卡顿或请求超时。
- 数据库查询（如搜索物品）在数据量达到1000条时，响应时间不超过1秒。

#### 2.2 安全要求

- 用户密码不得以明文形式存储，需进行加密处理。
- 系统需具备基础权限控制：未登录用户只能浏览物品列表，无法进行购买、发布、留言等操作。
- 防止常见Web漏洞：对用户输入进行过滤，防止SQL注入；对页面输出进行转义，防止XSS攻击。
- 订单金额扣减需使用数据库事务保证一致性，避免超扣或重复扣款。

#### 2.3 兼容性要求

- 前端界面应适配主流分辨率（1920×1080、1366×768）。
- 支持以下浏览器的最新版本：
  - Google Chrome
  - Microsoft Edge
  - Mozilla Firefox
- 暂不考虑移动端适配，以PC端Web页面为主。

## 三、系统设计

### 1. 系统架构

&emsp;&emsp;本系统采用 MVC（Model-View-Controller）三层架构，将系统分为表现层、业务逻辑层和数据访问层，确保各层职责清晰，便于小组成员分工并行开发。

**架构分层说明：**

| 层级 | 技术选型 | 职责 |
| :--- | :--- | :--- |
| 表现层 (View) | HTML5 + CSS3 + JavaScript | 负责用户界面展示，接收用户操作，发送 HTTP 请求，渲染后端返回的数据 |
| 控制层 (Controller) | Spring Boot (Controller) | 接收前端请求，调用业务逻辑层进行处理，返回响应数据 |
| 业务逻辑层 (Service) | Spring Boot (Service) | 处理核心业务逻辑，如金额扣减、权限校验等 |
| 数据访问层 (DAO) | MyBatis / JPA | 封装数据库操作，与 MySQL 进行数据交互 |
| 数据库层 | MySQL | 存储用户、物品、订单等数据 |

**系统架构图：**

![系统架构图](./assets/fig_architecture.png)

> 上图展示了从用户浏览器到数据库的完整请求处理流程：
> 1. 用户在浏览器进行操作 → 2. 请求发送至 Controller → 3. Controller 调用 Service 层执行业务逻辑 → 4. Service 调用 DAO 层操作数据库 → 5. 返回结果逐层回传 → 6. 前端更新页面显示

### 2. 模块设计

系统主要划分为以下六个核心模块：

#### （1）二手交易模块

| 项目 | 内容 |
| :--- | :--- |
| 功能 | 物品发布、分类浏览、关键词搜索、详情查看、购买下单 |
| 主要流程 | 用户登录 → 填写物品信息并发布 → 物品进入在售列表 → 买家搜索/浏览 → 查看详情 → 确认购买 → 系统校验余额 → 扣款成功 → 生成订单 |
| 关键设计 | 购买前需校验物品状态是否为“在售”；购买后自动将物品状态改为“已售”，防止重复购买 |

#### （2）资产与账户模块

| 项目 | 内容 |
| :--- | :--- |
| 功能 | 余额查询、模拟充值、购买结算、碳积分查询 |
| 主要流程 | 用户输入充值金额 → 系统增加账户余额 → 交易时校验余额 → 扣除相应金额 |
| 关键设计 | 充值记录和消费记录均写入数据库，便于后续追溯；余额变动使用数据库事务保证一致性 |

#### （3）留言板模块

| 项目 | 内容 |
| :--- | :--- |
| 功能 | 在物品详情页留言、查看留言、回复留言 |
| 主要流程 | 已登录用户输入留言内容 → 提交 → 留言保存并显示在留言板中 |
| 关键设计 | 只有登录用户才能留言，未登录用户只能查看已有留言；每条留言关联对应的物品ID和用户ID |

#### （4）状态管理模块

| 项目 | 内容 |
| :--- | :--- |
| 功能 | 物品状态（在售/已售/已下架）、订单状态（已完成/已取消） |
| 关键设计 | 物品购买成功后自动更新状态为“已售”；管理员可手动将违规物品状态设为“已下架” |

#### （5）系统管理后台模块

| 项目 | 内容 |
| :--- | :--- |
| 功能 | 用户管理、物品审核/监管、交易记录查看配置 |
| 关键设计 | 管理员具有独立的权限，可禁用违规用户账号，强制下架违规物品，查看全平台交易记录 |

## 四、系统实现 

### 1. 关键技术

#### 1.1 前端框架

&emsp;&emsp;前端采用原生 HTML5、CSS3 和 JavaScript 构建，便于小组成员快速上手。使用 CSS Flexbox 和 Grid 实现响应式布局，适配不同分辨率；通过原生 JavaScript 处理表单提交、异步请求（Ajax）、DOM 操作等；使用 fetch 或 XMLHttpRequest 调用后端 RESTful API，传递 JSON 格式数据。
| 功能模块 | 技术实现 | 核心特点 |
|---------|---------|---------|
| 用户认证 | MD5双重加密 + JWT | 高安全性的密码保护 |
| 路由管理 | Vue Router + 守卫 | 前端权限控制 |
| HTTP通信 | Axios + 拦截器 | 统一请求管理 |
| 数据可视化 | ECharts | 实时趋势展示 |
| 富文本编辑 | Wangeditor | 复杂内容编辑 |
| UI组件库 | Element UI | 企业级UI |
| 文件上传 | Element上传组件 | 图片处理和预览 |
| 本地存储 | sessionStorage | 会话状态管理 |

#### 1.2 后端框架

&emsp;&emsp;本系统采用 Spring Boot 作为后端开发框架，Spring Boot 提供了自动配置功能，减少了传统 Spring 项目中繁琐的 XML 配置，能够快速搭建 Web 应用。

- **Spring Boot**：提供整体框架与自动配置能力。
- **MyBatis**：用于持久层操作，便于编写复杂 SQL。
- **JWT**：用于用户登录认证和身份识别。
- **AOP**：实现分页参数处理、接口权限校验、操作日志记录。
- **ThreadLocal**：在一次请求过程中保存当前用户信息。
- **RESTful 风格接口**：前端以统一的 HTTP 方法访问后端资源。
- **统一响应封装**：使用 `Result`、`ApiResult`、`PageResult` 统一返回格式。

#### 1.3 数据库

&emsp;&emsp;本系统使用 MySQL 作为关系型数据库，存储用户信息、物品清单、订单记录、积分记录等数据。MySQL 开源免费，配置简单，适合课程项目开发。且MySQL 的 InnoDB 引擎支持事务，与 Spring 事务管理配合，确保金融相关操作的可靠性（如扣款与订单生成需同时成功或同时回滚）。

### 2. 界面展示

#### 2.1 引言与前端视觉体验

##### 2.1.1 前端视觉设计与用户体验
* **界面风格：** 采用清新温和的校园主题色（明黄色 `#FEDF46` 作为主色调，搭配高雅的灰蓝色与护眼底色），营造亲切、充满活力的校园氛围。

```vue
<template>
    <div class="login-container">
        <div class="login-panel">
            <!-- 左侧图片区域 -->
            <div style="width: 300px;padding: 40px;">
                <img src="/bag.png" style="width: 350px;" />

            <!-- 右侧登录表单区域 -->
            <div class="right-login">
                <h2>校园二手交易平台</h2>
                <!-- 账号输入框 -->
                <input v-model="act" class="act" placeholder="输入账号" />
                <!-- 密码输入框 -->
                <input v-model="pwd" class="pwd" type="password" placeholder="输入密码" />
                <!-- 登录按钮 -->
                <span class="login-btn" @click="login">立即登录</span>
                <!-- 跳转到注册页面 -->
                <span class="no-act" @click="toDoRegister">点此注册</span>
            </div>
        </div>
    </div>

<script>
import request from "@/utils/request.js";
import { setToken } from "@/utils/storage.js";
import md5 from 'js-md5';

export default {
    name: "Login",
    data() {
        return {
            act: '',        // 账户
            pwd: '',        // 密码
        }
    },
    methods: {
        async login() {
            // 1. 校验账户和密码不能为空
            if (!this.act || !this.pwd) {
                this.$swal.fire({
                    title: '填写校验',
                    text: '账号或密码不能为空',
                    icon: 'error',
                    showConfirmButton: false,
                    timer: 1300,
                });
                return;
            }
            
            // 2. 密码使用MD5加密（双重加密）
            const hashedPwd = md5(md5(this.pwd));
            const paramDTO = { userAccount: this.act, userPwd: hashedPwd };
            
            try {
                // 3. 发送登录请求到后端
                const { data } = await request.post(`user/login`, paramDTO);
                
                // 4. 检查响应状态
                if (data.code !== 200) {
                    this.$swal.fire({
                        title: '登录失败',
                        text: data.msg,
                        icon: 'error',
                        showConfirmButton: false,
                        timer: 1300,
                    });
                    return;
                }
                
                // 5. 存储token到sessionStorage
                setToken(data.data.token);
                
                // 6. 根据用户角色进行页面跳转
                setTimeout(() => {
                    const { role } = data.data;
                    this.navigateToRole(role);  // role: 1=管理员, 2=普通用户
                }, 1300);
                
            } catch (error) {
                console.error('登录请求错误:', error);
                this.$message.error('登录请求出错，请重试！');
            }
        },
        
        // 角色导航
        navigateToRole(role) {
            switch (role) {
                case 1:
                    this.$router.push('/admin');  // 管理员后台
                    break;
                case 2:
                    this.$router.push('/user');   // 普通用户前台
                    break;
                default:
                    console.warn('未知的角色类型:', role);
                    break;
            }
        }
    }
};
</script>
```

#### 3.2 后端核心代码

本项目后端采用经典的三层架构：

```text
Controller 层  →  Service 层  →  Mapper 层  →  MySQL 数据库
```

| 层级 | 职责 | 典型代码 |
|------|------|----------|
| Controller 层 | 接收前端请求、解析参数、返回统一响应 | `UserController`、`ProductController` |
| Service 层 | 编写核心业务逻辑，完成校验、组装、状态流转 | `UserServiceImpl`、`OrdersServiceImpl` |
| Mapper 层 | 与数据库交互，执行增删改查 | `UserMapper`、`ProductMapper` |
| 数据库层 | 存储用户、商品、订单、消息、评论等业务数据 | MySQL |

##### 3.2.1 统一响应封装

项目中定义了统一返回体：

- `Result<T>`：基础返回结构，包含 `code` 和 `msg`
- `ApiResult<T>`：在基础返回体上增加 `data`、`total`
- `PageResult<T>`：专门用于分页返回

例如在Controller的登录接口
```java
@PostMapping("/login")
public Result<String> login(@RequestBody User user){
    String token = userService.login(user);
    return Result.success(token);
}
```
登录成功会返回
```json
{
"code": 200,
"msg": "success",
"data": "token字符串"
}
```
项目中所有接口均返回 Result<T> 对象，而不是直接返回数据。
这样可以统一前后端的数据交互格式，方便前端解析。

**`ApiResult` 的作用**

`ApiResult` 提供了多种静态工厂方法，例如：

```java
ApiResult.success()
ApiResult.success(data)
ApiResult.success(data, total)
ApiResult.success("登录成功", map)
ApiResult.error("密码错误")
```

它的价值在于：

1. **统一接口返回格式**，前端处理更简单；
2. **减少重复代码**，Service 层只需关注业务；
3. **分页与非分页复用同一套响应体系**。

**`PageResult` 的作用**

分页接口通常返回两类信息：

- 当前页数据列表
- 满足条件的总记录数

因此 `PageResult.success(data, total)` 适合用于列表查询场景，例如：

- 用户查询
- 商品查询
- 订单查询
- 评论查询
- 消息查询
- 操作日志查询

**Token 生成**

```java
public static String toToken(Integer id, Integer role) {
    JwtBuilder jwtBuilder = Jwts.builder();
    return jwtBuilder.setHeaderParam("typ", "JWT")
            .setHeaderParam("alg", "HS256")
            .claim("id", id)
            .claim("role", role)
            .setSubject("用户认证")
            .setExpiration(new Date(System.currentTimeMillis() + time))
            .setId(UUID.randomUUID().toString())
            .signWith(SignatureAlgorithm.HS256, privateKey)
            .compact();
}
```

这里的`JwtUtil.toToken(id, role)` 负责创建 token，并把以下信息写入 token：

- 用户 ID
- 用户角色
- 过期时间（7 天）
- 唯一随机 ID

生成 token 后，登录接口返回给前端保存。后续请求时，前端在请求头中携带 `token`。

**Token 解析**
```java
public static Claims fromToken(String token) {
    JwtParser jwtParser = Jwts.parser();
    Jws<Claims> claimsJws;
    try {
        claimsJws = jwtParser.setSigningKey(privateKey).parseClaimsJws(token);
        return claimsJws.getBody();
    } catch (Exception e) {
        return null;
    }
}
```
这里的`JwtUtil.fromToken(token)` 用于解析 token：

- 解析成功：返回 `Claims`
- 解析失败：返回 `null`

这样可以在拦截器和权限切面中快速判断用户是否登录、身份是否合法。

##### 3.2.2 ThreadLocal 保存当前用户

项目定义了 `LocalThreadHolder`：

```java
private static final ThreadLocal<Map<String, Integer>> USER_HOLDER = new ThreadLocal<>();
```

它的作用是：

1. 从 token 中解析出用户信息后，存入当前线程；
2. 业务代码中可以随时通过 `LocalThreadHolder.getUserId()` 获取当前登录用户；
3. 请求结束后通过 `clear()` 释放资源，避免内存泄漏。

保存用户信息
```java
public static void setUser(Integer userId, Integer roleId) {
Map<String, Integer> map = new HashMap<>();
map.put("userId", userId);
map.put("roleId", roleId);
USER_HOLDER.set(map);
}
```
获取用户 ID
```java
public static Integer getUserId() {
return USER_HOLDER.get().get("userId");
}
```
获取角色 ID
```java
public static Integer getRoleId() {
return USER_HOLDER.get().get("roleId");
```

```java
public Object auth(ProceedingJoinPoint proceedingJoinPoint) throws Throwable {
    ServletRequestAttributes attributes = (ServletRequestAttributes) RequestContextHolder.getRequestAttributes();
    HttpServletRequest request = attributes.getRequest();
    String token = request.getHeader("token");
    if (token == null) {
        return ApiResult.error("身份认证失败，请先登录");
    }
    Claims claims = JwtUtil.fromToken(token);
    if (claims == null) {
        return ApiResult.error("身份认证失败，请先登录");
    }
    Integer userId = claims.get("id", Integer.class);
    Integer roleId = claims.get("role", Integer.class);
    // 获取被拦截方法的签名
    MethodSignature signature = (MethodSignature) proceedingJoinPoint.getSignature();
    // 获取方法上的@Protector注解实例
    Protector protectorAnnotation = signature.getMethod().getAnnotation(Protector.class);
    if (protectorAnnotation == null) {
        return ApiResult.error("身份认证失败，请先登录");
    }
    String role = protectorAnnotation.role();
    // 验证用户角色
    if (!"".equals(role)) {
        if (!Objects.equals(RoleEnum.ROLE(Math.toIntExact(roleId)), role)) {
            return ApiResult.error("无操作权限");
        }
    }
    // 放在 ThreadLocal里面，当前线程都可用
    LocalThreadHolder.setUserId(userId, roleId);
    Object result = proceedingJoinPoint.proceed();
    // 请求结束，释放资源
    LocalThreadHolder.clear();
    return result;
}
```

```java
    evaluationsMapper.save(evaluations);
    return ApiResult.success("评论成功");
}
```
`EvaluationsServiceImpl.insert()` 的流程：

1. 设置评论者为当前登录用户；
2. 查询当前用户信息；
3. 如果用户处于禁言状态，则禁止评论；
4. 填充创建时间；
5. 保存评论。

**评论列表 `list`**
````java
public Result<Object> list(Integer contentId, String contentType) {
    List<CommentParentVO> parentComments = evaluationsMapper.getParentComments(contentId, contentType);
    setUpvoteFlag(parentComments);
    Integer count = evaluationsMapper.totalCount(contentId, contentType);
    return ApiResult.success(new EvaluationsVO(count, parentComments));
}
````
`list(contentId, contentType)` 会返回某个内容下的完整评论树。

核心流程：

1. 查询父评论；
2. 为每个父评论设置点赞状态和点赞数；
3. 遍历子评论，同样设置点赞状态和点赞数；
4. 统计总评论数；
5. 返回 `EvaluationsVO`。

**点赞状态处理**
```java
private void setUpvoteFlag(List<CommentParentVO> parentComments) {
    String userId = LocalThreadHolder.getUserId().toString(); // 预先获取用户ID
    parentComments.forEach(parentComment -> {
        parentComment.setUpvoteFlag(isUserUpvote(parentComment.getUpvoteList(), userId));
        parentComment.setUpvoteCount(countVotes(parentComment.getUpvoteList()));
        Optional.ofNullable(parentComment.getCommentChildVOS())
                .orElse(Collections.emptyList())
                .forEach(child -> {
                    child.setUpvoteFlag(isUserUpvote(child.getUpvoteList(), userId));
                    child.setUpvoteCount(countVotes(child.getUpvoteList()));
                });
    });
}
```
`setUpvoteFlag()` 的逻辑比较重要：

- 当前用户 ID 会被提前取出；
- 遍历评论与子评论；
- 根据点赞字符串判断当前用户是否已点赞；
- 同时统计点赞总数。

这说明评论点赞数据不是单独建表统计，而是通过字符串记录用户 ID，再在读取时做解析和计算。

```java
public Result<List<ChartVO>> productShelvesInfo(Integer day) {
```

##### 3.2.20 Mapper 层设计说明
Mapper 层负责与 MyBatis 交互，是整个业务的数据库入口。

**主要 Mapper 及职责**

| Mapper | 作用 |
|--------|------|

**Mapper 与 Service 的配合方式**

Service 层通常会先进行业务判断，再调用 Mapper：

- 先查是否重复操作；
- 先判断库存；
- 先验证角色；
- 再执行 insert / update / delete。

保证数据库操作尽量发生在“合法业务条件”下。

#### 1.2 部署步骤

##### （1）数据库初始化

**第一步：打开cmd，输入以下指令，登录 MySQL**

```bash
#root改成你自己的数据库用户名,一般会是root
mysql -u root -p 
```

**第二步：执行以下 SQL 语句，初始化数据库**

```sql
-- 1、创建数据库
CREATE DATABASE campus-product CHARACTER SET utf8mb4 COLLATE utf8mb4_bin;

-- 2、进入刚创建的数据库
USE campus-product;

-- 3、导入表结构
SOURCE ../../init_table.sql; -- 这里填你电脑上init_table.sql的文件路径

-- 4、导入初始数据
SOURCE ../../init_data.sql; -- 这里填你电脑上init_data.sql的文件路径
```

##### （2）后端启动

**第一步：修改数据库连接配置**

```text
1、找到 backend/src/main/resources/application.yml
2、修改 spring.datasource.username 和 spring.datasource.password ,改成你自己的数据库用户名和密码
```

**第二步：启动后端**

```bash
在 IDEA 中运行 CampusProductApplication.java
# 后端默认运行在 http://localhost:21090
```

##### （3）前端启动

**在终端执行以下命令**
```bash
cd frontend
npm install        # 安装依赖
npm run serve      # 启动开发服务器
# 前端默认运行在 http://localhost:21091
```

##### （4）访问系统

打开浏览器访问 `http://localhost:21091`

## 七、项目总结 

### 1. 成果总结
  经过团队五名成员的共同努力，我们成功设计并实现了"校园二手交易系统"。项目采用 Spring Boot + Vue.js + MySQL 技术栈，实现了前后端分离的完整 Web 应用。系统覆盖了用户注册登录、商品发布与管理、商品浏览与搜索、收藏互动、下单购买与退款、评论互动、消息通知、个人信息管理等完整的二手交易业务流程，同时为管理员提供了包括仪表盘、用户管理、商品管理、订单管理、类别管理、评论管理、消息管理、互动管理、日志管理在内的九大后台管理功能。

  在技术实现上，系统运用了 JWT Token 认证、AOP 切面编程（权限保护、分页处理、操作日志自动化）、ThreadLocal 用户上下文、MyBatis ORM 映射、MD5 双重密码加密等关键技术，体现了良好的软件工程实践。

### 2. 不足与改进方向

（1）图片存储待优化： 当前图片以本地文件系统存储，随着数据量增长可能成为性能瓶颈。后续可迁移至对象存储服务。

（3）移动端适配： 当前界面针对 PC 端优化，暂不支持移动端。后续可开发微信小程序或响应式移动端页面。

（4）搜索功能升级： 当前仅支持按商品名称等字段的模糊查询，后续可引入 ElasticSearch 实现全文检索和智能推荐。
